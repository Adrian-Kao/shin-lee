## 1. 題目說明｜我們在做什麼

**一句話**：把專利 Office Action（OA，審查意見通知函）的答辯流程半自動化，
**律師仍對最終答辯狀負完全責任**。

- 輸入：一份 OA（PDF / 文字）＋ 對應專利
- 輸出：逐項拒絕對應、引用法源、答辯草稿、期日試算
- 定位：不是取代律師，是「資深助理 + 不會抄錯的書記」
- 對象：專利事務所、企業法務、in-house IP 團隊

講稿: 重點是「協作」而非「自動產生送件」。AI 出草稿，律師逐句簽核。

---

## 2. 痛點｜現況有多痛

| 痛點 | 現況 | 後果 |
|------|------|------|
| ⏱️ **耗時** | 1 件 OA 答辯純人工 **8–12 小時** | 律師時間被低價值抄寫吃掉 |
| 🎯 **幻覺風險** | 引用法條 / 前案容易抄錯 | 答辯被駁、專業信譽受損 |
| 📅 **期日易錯** | 多國期日、假日順延手算 | 算錯 = 失權，無法挽回 |
| 🔒 **資料外流** | 客戶機密絕不能進公有雲 | 直接用 ChatGPT = 違反保密義務 |

講稿: 前三個是「效率與正確性」，第四個「保密」是律師業不能用一般 AI 工具的根本原因——這也是我們最大的差異化。

---

## 3. 解方｜PatentMind 怎麼解

對應上面四個痛點，逐一拆解：

- ⏱️ **耗時 → 自動拆解 + RAG 檢索 + 草稿生成**
  幾分鐘產出「拒絕對應表 + 引用 + 草稿」，律師從 0→1 變成 1→完稿。
- 🎯 **幻覺 → Grounded Citation + Verifier 雙模型**
  每個引用必須來自檢索到的真實來源；第二個模型把關，抄不到就不准寫。
- 📅 **期日 → 多國 / 多時區 + 假日自動順延**
  落在週末或國定假日自動 roll-forward，台灣 + 美國規則內建。
- 🔒 **保密 → 強制去識別化 + 機密案件強制走地端 LLM**
  任何文字進 LLM 前一定先 redact；機密等級案件自動改用地端模型，不出機房。

> 核心信念：**AI 負責草稿與比對，律師負責判斷與簽核。**

講稿: 每個解方都有對應的程式碼落地（不是 slideware），下一頁示範流程。

## 4. 使用流程｜律師的一天

```

 ▼                ▼                  ▼                    ▼               ▼

(看得到才       (自動去識別)   3. 產生答辯草稿      全簽完才能出稿      audit 紀錄
 能開案)                       4. Verifier 把關                        + hash chain
                               5. 期日試算
```

**Demo 可現場操作的亮點**

| 動作 | 觀察 |
|------|------|
| Carol 登入開不屬於她的案件 | 403 被擋（case ACL） |
| 按「預覽 redaction」 | email / 電話 / 案號被換成 placeholder |
| hover 引用 pill | 顯示來源專利 + 段落 + 原文 |
| 機密案 (`-CONF`) 重跑 | audit 顯示 model 變地端 `llama` |
| 同案連按兩次分析 | 第二次走 cache，token = 0 |

講稿: 這整條 `login → redaction → RAG → grounded draft → verifier → deadline → audit` 已經端到端跑通（`verify.sh` 全綠）。

## 5. 技術架構｜兩層、職責清楚

```
┌──────────────── Frontend (Vite + React SPA) ────────────────┐
│   Login → Analyze → Draft 簽核 → Audit                       │
└───────────────────────────┬─────────────────────────────────┘
                            │ /api (proxy)
                            ▼
┌──────────── Gateway :8000（厚 Gateway，業務編排）────────────┐
│  Auth → RateLimit → Mask(去識別) → Cache → Orchestrator → Audit │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP（機房內網）
                            ▼
┌──────────── AI Engine :8001（純推論，無業務狀態）────────────┐
│  parse_oa → retrieve(RAG) → draft → verify → deadline        │
│                 └── LLM Router（雲端 / 地端，依機密等級）       │
└───────────────────────────┬─────────────────────────────────┘
                ┌───────────┴───────────┐
                ▼                       ▼
         Vector DB (Qdrant)        LLM（雲端 / 地端）
```

**設計重點**
- **Gateway 厚、AI Engine 薄**：Gateway 編排流程，AI Engine 只做推論
- **可替換**：vector store / cache / LLM 都抽象化，mock ↔ 正式一鍵切換
- 技術棧：FastAPI · React/Vite · Qdrant · 多模型 LLM router
- 背後是 **20 項架構決策**（`docs/DECISIONS.md`），每項都有對應程式碼

講稿: 兩個關鍵紀律——Gateway 永遠不直接打 LLM；AI Engine 永遠不存業務狀態。職責分離讓安全邊界清楚。

## 5b. 安全與信任｜為什麼律師敢用

八條「不可違反」的設計鐵則（都有程式碼強制）：

| # | 鐵則 | 防的是 |
|---|------|--------|
| 1 | 進 LLM 前**強制去識別化** | 客戶機密外流 |
| 2 | 機密案件**強制走地端 LLM** | 敏感資料出機房 |
| 3 | 引用**必須來自檢索來源** + Verifier 把關 | AI 幻覺 / 抄錯法源 |
| 4 | 每個請求**剛好一筆 append-only 稽核** + hash chain | 事後不可竄改、可追責 |
| 5 | 每個請求都檢查 **case_id ACL** | 越權看別人的案件 |
| 6 | 四層 **Prompt Injection 防禦** | 惡意 OA 操控 AI |
| 7 | LLM 呼叫前先檢**配額**，再檢**成本熔斷** | 失控費用 |
| 8 | 租戶隔離（`tenant_id` + per-user cache） | 跨客戶資料混用 |

> **合規定位**：Hybrid 部署——原文留地端，只有去識別化後的檢索結果才上雲。

講稿: 這八條是整個專案的價值核心。一般 AI 工具給不出第 1、2、4、5 條，而這正是律師業的及格線。
