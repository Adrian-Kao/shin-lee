# Contributing to PatentMind AI

Thanks for your interest in contributing! PatentMind is a reference
architecture for **secure, audited LLM pipelines in regulated domains**
(legal / patent prosecution). Contributions that strengthen the security,
correctness, or clarity of that reference are especially welcome.

## Code of Conduct

This project follows the [Contributor Covenant](CODE_OF_CONDUCT.md).
By participating, you are expected to uphold it.

## Ground rules (read these first)

This project handles patterns built for confidentiality. Two rules are
non-negotiable:

1. **Never commit real, unpublished, or personally-identifiable data.**
   No real Office Actions, client patents, examiner names/contacts, or
   secrets. All sample data under `data/cases/` is synthetic — generated by
   `data/cases/synthetic_cases.py`. If you need a fixture, add a synthetic
   one. See [SECURITY.md](SECURITY.md).
2. **Never weaken a design invariant** without discussion. The eight
   invariants in [`CLAUDE.md` §4](CLAUDE.md) (mandatory redaction before any
   LLM call, grounded-citation verifier, per-request audit row, `case_id`
   ACL on every request, etc.) are the whole point of the project. A PR that
   bypasses one will be asked to justify it or route around it.

## Development setup

Prerequisites: **Python 3.11+**, **Node 20+**, and (optionally) Docker.

```bash
# Backend (full POC) — starts gateway :8000 + ai_engine :8001, seeds demo data
bash scripts/start_backend.sh

# End-to-end verification — must print "ALL CHECKS PASSED"
bash scripts/verify.sh

# Frontend
cd frontend && npm install && npm run dev   # http://localhost:5173
```

Copy `.env.example` to `.env` and adjust as needed. The defaults run fully
in **mock mode** (`LLM_MODE=mock`, in-memory vector store + cache) with no
external API keys required.

## Before you open a PR

Run the same checks CI runs (`.github/workflows/ci.yml`):

```bash
# Python lint + tests
ruff check .
pytest tests/unit tests/integration -v

# Frontend build + smoke
cd frontend && npm run build && npx playwright test
```

We also ship a **pre-commit** config — install it once and it runs on every
commit:

```bash
pip install pre-commit && pre-commit install
```

Environment for the test suite (mock backends, no network):

```
LLM_MODE=mock  VECTOR_BACKEND=memory  EMBEDDING_BACKEND=mock  CACHE_BACKEND=memory
```

## Pull request guidelines

- **One logical change per PR.** Keep diffs reviewable.
- **Add or update tests.** Security-relevant changes (auth, masking, ACL,
  audit, rate limiting) should come with a test under `tests/integration/`.
- **Keep `verify.sh` green.** It encodes the architectural invariants; if it
  goes red, an invariant broke — fix that before adding features.
- **Update docs** when you change behavior. The Q→code map lives in
  [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md); decisions in
  [`docs/DECISIONS.md`](docs/DECISIONS.md).
- **Describe the security impact** of your change in the PR template, even if
  it's "none".

## Finding something to work on

- `TODO(claude-code)` markers across the codebase flag stubs to harden.
- [`CLAUDE.md` §3](CLAUDE.md) ("What's stubbed") and §5 ("Suggested next
  features") list prioritized work.
- Issues labeled `good first issue` are scoped for newcomers.

## Reporting bugs / requesting features

Use the [issue templates](.github/ISSUE_TEMPLATE/). For anything that looks
like a **security vulnerability, do not open a public issue** — follow
[SECURITY.md](SECURITY.md) instead.
